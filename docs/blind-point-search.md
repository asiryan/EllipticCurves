# Самостоятельное расширение набора точек

`tools/RankHunt/blind_search.py` получает целочисленное уравнение Вейерштрасса,
известные рациональные точки и бюджет времени. Он ищет дополнительные точки
и доказывает нижнюю границу. Параметров эталона, списка искомых точек, матриц
перехода к опубликованному базису и сценария воспроизведения у него нет.

Это поисковый модуль для будущего поиска рекордных кривых. Начальные точки
может выдавать конструктор семейства. Получение первых точек по одному
уравнению, вычисление точного ранга, доказательство полноты группы и
построение полного пространства Сельмера в этот модуль не входят.

## Фиксированная политика версии 3

1. Проверить уравнение и все входные точки. Использовать только поля `ainvs`
   и `points`; остальные метаданные не управляют поиском.
2. Выбрать независимые столбцы матрицы локальных характеров. Затем отдельно
   доказать независимость выбранных точек существующим сертификатором C#.
   Ненулевой образ точки кручения сам по себе не принимается за независимость.
3. Из выбранных точек построить ограниченный пул целочисленных комбинаций,
   используя канонические высоты и LLL. Половина опор берётся из ограниченного
   поиска, развивающего сначала векторы с меньшей вычисленной высотой.
   Вторая половина распределяется между комбинациями с 2–8 ненулевыми
   коэффициентами: внутри каждой группы выбираются самые короткие из
   фиксированной случайной выборки. Для размерности меньше 3 используется
   только первый способ. Рассматривается не более `16*anchors` кандидатов;
   случайные попытки также ограничены. Коэффициенты в LLL-базисе ограничены
   по модулю 3, сумма модулей — 12. По умолчанию выбираются 2048 опор.
   Это эвристическая выборка, а не доказанный список всех кратчайших векторов.
   Все равенства проверяются точной арифметикой Python.
4. Для каждой опоры построить квартику, минимизировать и редуцировать её.
   Чередовать три порядка обработки: размер коэффициентов, каноническая
   высота опоры и фиксированная случайная перестановка. Эти признаки не
   гарантируют нахождение нового независимого направления.
5. Перебирать прямоугольники для рациональной координаты `n/d`. Показатель
   произведения границ принимает значения `20,24,28,32,36,40`, показатель
   границы знаменателя — `0,4,8,12,16,20`, с условием `D <= N`.
   Для каждой пары `N,D` пройти текущий список моделей. Точки на бесконечности
   квартики проверяются отдельно.
6. Каждые 32 задания один раз объединять находки с архивом и проверять нижнюю границу
   предыдущего независимого базиса вместе с новыми точками.
   При её росте строить новый пул опор из собственного результата. Точки,
   не увеличившие текущий сертификат, сохраняются.
7. Остановиться по цели, бюджету, исчерпанию политики или ошибке. Отсутствие
   прироста не означает отсутствия других независимых точек.

Каждое задание имеет отдельный лимит времени; по умолчанию работают два
процесса PARI. Канонические высоты нужны только для выбора комбинаций.
Независимость доказывается точной арифметикой, а не численным определителем.
В поиске не вызываются `ellrank`, `ellrankinit`, `ell2cover` или аналитический
ранг. Не требуется совпадения координат с опубликованным списком.

## Что именно даёт смена модели

После замены `V = 2y + a1*x + a3` уравнение имеет вид
`V² = 4x³ + b2*x² + 2*b4*x + b6`. Для известной опоры `(x0,V0)`
пересекаем кривую прямой `V = V0 + t*(x-x0)`. Удалив известный корень
`x=x0`, получаем квадратное уравнение. Его дискриминант равен

```text
D(t) = t⁴ - 2(12*x0+b2)t² + 32*V0*t
       + b2² - 8*b2*x0 - 48*x0² - 32*b4.
```

Рациональная точка `z²=D(t)` даёт точку исходной кривой:
`x=(t²-b2-4*x0+z)/8`, `y=(V0+t*(x-x0)-a1*x-a3)/2`.
Поэтому ограниченный поиск ведётся в другой рациональной координате.
Минимизация и редукция могут сделать координаты ещё не найденных точек
доступнее для перебора. Код сохраняет обратные преобразования и проверяет
полученные точки на исходном уравнении.

Комбинации известных точек сами по себе не увеличивают нижнюю границу:
они только дают другие опоры. Прирост появляется, когда поиск на новой
модели действительно находит точку, независимую от уже известных.
Ни LLL, ни редукция модели не гарантируют такой прирост за заданное время.

При положительном ранге рациональных точек бесконечно много. Практическая
цель этого модуля — найти заданное число независимых точек, а не перечислить
«все точки». Даже достижение 31 здесь означает доказательство `rank >= 31`,
а не полноты найденной группы.

## Вход и запуск

JSON должен содержать пять коэффициентов `[a1,a2,a3,a4,a6]` и массив точек:

```json
{"ainvs":["0","0","0","-25","4"],"points":[["0","2"]]}
```

Из корня проекта, после сборки RankHunt и при наличии локального PARI:

```powershell
python tools/RankHunt/blind_search.py --input curve-with-seeds.json --output artifacts/blind-search/my-run --seconds 600 --target 31
```

Текущая версия требует, чтобы локальный сертификат смог извлечь непустой
набор с доказанной независимостью всех выбранных точек. В частности, её
консервативная обработка рационального 2-кручения может отклонить вход,
с которым более общий алгоритм смог бы работать. Пустой набор не поддерживается.

`--seconds` — бюджет данного запуска; `--job-seconds` — лимит одного задания;
`--anchors` — предел размера пула; `--workers` — число рабочих процессов.
Бюджет включает подготовку и проверки, но их завершение может дать небольшое
превышение. Стоимость подготовки некоторых моделей сама по себе существенна.

## Сохранение состояния и проверяемость

В каталоге запуска сохраняются исходные точки, конфигурация, копии Python-кода
и его SHA-256, поколения опор и их целочисленные коэффициенты, GP-скрипты,
stdout/stderr, точки каждого задания, сертификат, события прироста и состояние.
Итоговые `points.json` и `certificate.json` обновляются атомарной заменой файлов.

Продолжение с теми же аргументами:

```powershell
python tools/RankHunt/blind_search.py --input curve-with-seeds.json --output artifacts/blind-search/my-run --seconds 600 --target 31 --resume
```

При продолжении проверяется совпадение входа, кода и политики. Завершённые
попытки не повторяются, включая попытки, достигшие лимита. Тайм-аут не отмечает
область как исчерпанную: в журнале есть `timed_out` и `finished`. Повтор с иными
лимитами требует нового каталога. Внутреннее состояние PARI не восстанавливается.

В Python установлен контроль доступа к данным: читать посторонние JSON и
другие данные проекта, кроме входа и каталога запуска, запрещено. Допустимые
чтения записываются в `data-reads.json`. Это проверяемая граница данных, а не
защитная песочница ОС. Внешние программы получают только сгенерированные
арифметические скрипты и собственные файлы результата.

После завершения запуска выполняется отдельный аудит:

```powershell
python tools/RankHunt/audit_blind_search.py --run artifacts/blind-search/my-run --output results/my-run-audit
```

Аудитор заново восстанавливает каждую использованную опору как точную
комбинацию ранее найденных точек, сверяет GP-скрипты и фактический stdout,
проверяет происхождение итогового архива. Выбранные независимые точки
проверяются отдельной реализацией сертификата на Python. В результат
копируются этот проверяющий код, сами точки, сертификат и контрольные суммы.
Для повторного аудита нужен новый выходной каталог.

## Эксперимент на ICARM302

Версия 1 самостоятельно достигла границы 24, но остановилась на подготовке
опор: `qfminim` ограничивал число сохраняемых векторов, а не объём полного
перебора. В версии 2 этот вызов заменён описанным выше ограниченным поиском.
Также проверяется предыдущий независимый базис с новыми находками, вместо
повторной проверки всего архива после каждого пакета. Полный архив сохраняется.

Версия 2 продолжила этот результат до 25. В версии 3 добавлены описанные
выше группы опор с большим числом ненулевых коэффициентов. Кроме того,
архив нормализуется один раз после пакета, вместо повторения той же работы
после каждого из 32 заданий. При 875 точках прежние 32 нормализации занимали
около 0,53 секунды на пакет. Версия 3 в отдельном запуске от исходных 17
достигла доказанной границы 31 за 240,828 секунды. Независимый аудит занял
11,831 секунды и подтвердил все 31 точку без дополнительных предположений.
Подробности, ограничения и команда повтора — в
[`blind-record-20260914.md`](blind-record-20260914.md).

Для этого эксперимента входные 17 точек заново вычислены из общих сечений
семейства при известном параметре. Смена базиса к опубликованным 17 отключена.
Алгоритм не читает опубликованные дополнительные 14 точек и не использует
выбранные по ним опоры, прямоугольники или короткие представители.

Кривая ранее использовалась при разработке методов, поэтому этот опыт
проверяет самостоятельное принятие решений во время запуска, но не является
независимой проверкой обобщения на ранее не исследованной кривой. Для оценки
обобщения потребуется отдельная выборка.
