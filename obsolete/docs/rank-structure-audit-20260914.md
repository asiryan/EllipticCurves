# Структура семейства №302: проверка и применение

14 сентября 2026 года. Новый архив полезен: он даёт 17 явных сечений семейства
ICARM №302 и квадратичную замену параметра с дополнительным сечением. Формулы
независимо проверены и подключены к `tools/RankHunt`. Рекорд ранга не улучшен.

Следующий этап уже выполнен: получены специализации с нижней границей 19,
построена база для их дальнейшей генерации и ускорена проверка. Подробности
в [отчёте о поиске ранга 19](rank19-search-20260914.md).

|---|---|
| Добавление сечений к 48 сохранённым кандидатам | Для всех 48 нижняя граница выросла с 3 до 17 |

| Тот же поиск: новая кривая при w=0 | 4,370 с; новых точек нет; граница 18 |

Это отдельные замеры, а не универсальная оценка сложности. Короткие поиски
использовали `pointed`, минимальную модель, высоту 100000, до 24/18 опорных точек,
512 МБ стека PARI и предел 30 с. Обе попытки завершились без ошибок и тайм-аута.

Ранг каждой сохранённой кривой сам по себе не изменился: улучшилась доказанная
нижняя граница благодаря новым известным точкам. Значения эвристических оценок
Mestre–Nagao остались прежними и доказательством ранга не стали.

Наш `tools/RankStructureAudit/audit.py` переводит математические выражения из
JSON в PARI/GP через ограниченный арифметический AST. Скрипты нового архива не
исполняются. SymPy не требуется. Получены следующие точные проверки:

- Для двух наборов по 17 сечений проверены уравнение кривой, коэффициенты JSON
  и ограничения степеней `deg x <= 4`, `deg y <= 6`.
- Дискриминант имеет степень 24, не имеет кратных корней и взаимно прост с c4.
  Взвешенная модель гладкая над бесконечностью; это эллиптическая K3-поверхность
  с 24 геометрическими слоями типа I1.
- Пересчитана матрица спаривания высот первого набора. Определитель равен 1092;
  все 17 ведущих главных миноров положительны.
- Проверены рациональная параметризация коники, факторизация, порождающая
  дополнительное сечение, и тождество уравнения для этого сечения над коникой.
- Координаты специализаций сверены точно. C# отдельно доказал границы 17, 17,
  31 и 18 для соответствующих наборов; альтернативный набор также дал 17.
- Разложение опубликованного набора ранга 31 проверено как 17 специализаций
  общих сечений плюс 14 конкретных опубликованных точек, с переносом модели.

Эти проверки дают общий ранг не меньше 17 над Q(T), а после замены — не меньше
18 над Q(w). Для исходной K3-поверхности общий ранг равен 17: это максимально
возможный ранг над Q(T) для эллиптической K3-поверхности над Q. Ограничение и
принцип построения семейств с границами 18 и 19 обсуждаются в
[статье Элкиса](https://arxiv.org/html/2608.25406v1). Его конкретное семейство
отличается от семейства №302. Исходная формула №302 опубликована в
[истории комментариев ICARM](https://elliptic-rank.icarm.cloud/curve/302/commentary-history).

В отдельных специализациях независимость может теряться. Например, наши 17
сечений при T=0 дают сертификат только 12; это не утверждение верхней границы.
Поэтому программа всегда заново проверяет конкретные точки. Насыщение группы
и верхние границы ранга отдельных кривых здесь не вычислялись. BSD и GRH для
приведённых нижних границ не используются.

Новая замена имеет вид

\[
T(w)=\frac{-423901w^2+39079980w+6293092321}
{1876775w^2+83273802w-27990104273}.
\]

Она параметризует конику
`U² = 54264759471843376 T² + 22048582273831768 T + 3049459337164321`.
При рекордном `T=164518/924945` правая часть равна квадратичному невычету 3
по модулю 19. Поэтому этот параметр не получается из рационального w.
Конструкция **не даёт 32-ю точку на рекордной кривой**. При w=0 получается
`T=-6293092321/27990104273`, и все 18 предъявленных точек независимы.

Реализация `tools/RankHunt/Structured302.cs` использует встроенные рациональные
коэффициенты из `Data/icarm302-sections.json`. Новые запуски `grid` сохраняют
кандидатов сразу с 17 сечениями. Команда `enrich` дополняет старые файлы в
отдельном каталоге, сохраняя прежние точки. Исторический `export --family
icarm302` оставлен с четырьмя элементарными точками для воспроизводимости.
Новые варианты экспорта — `icarm302-17` и `icarm302-18`; во втором случае
`--u/--v` задаёт w, в первом — T. Полюсы выбранных аффинных формул отвергаются.

Примеры из корня репозитория, PowerShell:

```powershell
dotnet build tools/RankHunt/RankHunt.csproj -c Release -p:RestorePackagesPath=C:\Users\Profit77\.nuget\packages -p:NuGetAudit=false
dotnet tools/RankHunt/bin/Release/net8.0/RankHunt.dll export --family icarm302-17 --u -58 --v 237 --output artifacts/my-rank17.json
dotnet tools/RankHunt/bin/Release/net8.0/RankHunt.dll export --family icarm302-18 --u 0 --v 1 --output artifacts/my-rank18.json
dotnet tools/RankHunt/bin/Release/net8.0/RankHunt.dll enrich --input-dir artifacts/rank-hunt/h10000 --output artifacts/rank-structure-audit/enriched-h10000
python tools/RankStructureAudit/audit.py
python tools/RankHunt/test_hunt.py
```

Восемь интеграционных тестов прошли, сборка без ошибок и предупреждений.
Проверены точные координаты двух независимых фикстур, сокращение параметра,
поведение при T=0, сохранение старых точек, а также прежние проверки поиска
и восстановления из контрольной точки. `audit.py` отдельно перепроверяет
структурные тождества. `experiments.py` повторяет 15 малых специализаций и
сохраняет сертификаты при наличии результатов предыдущих команд.

Долговременные результаты находятся вне игнорируемого Git каталога `artifacts`:

- `candidate-5037-2518.json` и соответствующий сертификат — усиленный прежний

- `audit.json`, `enrichment.json`, `experiments.json` — результаты проверок,

Практический следующий шаг — искать дополнительные независимые точки у
специализаций с уже известной границей 18 и исследовать вторую совместимую
квадратичную замену для возможной границы 19. Совместимость двух замен,
рациональные параметры и независимость новых точек надо доказывать отдельно.
Преимущество нового семейства по вероятности найти ранг 32 пока не измерено.
В исходном семействе больше 17 общих независимых сечений искать бессмысленно;
большие ранги возникают у особых специализаций или после смены базы.

Заявленные в архиве 8–12 секунд восстановления сечений заново не измерялись:
мы проверяли готовые формулы и их применение. Точный символический этап PARI
занял около 0,021 с. Это время проверки, а не открытия формул. Мировая новизна
конструкции из архива и новых специализаций не устанавливалась.
