# Поиск новых кривых с целью rank ≥ 32

Второй алгоритм объединяет конструктор кривых, отбор параметров и сохранённый
поиск дополнительных точек. Он имеет конечный вычислительный бюджет и выдаёт
проверенные нижние границы. Достижение 32 за этот бюджет не гарантируется.

## Сохранённый первый алгоритм

Архив [`point-engine-v3-20260914.zip`](../results/point-engine-v3-20260914.zip)
содержит код, исходные 17 точек, доказательство нижней границы 31, журналы
опорных находок, исходные сборки .NET и исполняемый файл PARI. Контрольные суммы
перечислены в [`манифесте`](../results/point-engine-v3-20260914.manifest.json).
Исходный коммит: `177b35110f01a9faf71dc4efb89e33c0a7487b5c`.

Архив проверен по контрольным суммам и восстановлен в отдельном каталоге.
Восстановленная программа с сохранёнными исполняемыми файлами прошла небольшой
реальный поиск с приростом 1 → 2. Для запуска нужны Windows, Python и .NET 8.

Второй алгоритм проверяет SHA-256 пяти файлов поискового ядра перед запуском.
Изменять их незаметно для новой кампании нельзя. Код первого алгоритма в этой
доработке не менялся; команды подготовки кандидатов добавлены отдельно.

## Конструктор и отбор

Используется опубликованное семейство ICARM302 с восстановленными общими
формулами 17 сечений. Выбирается рациональный параметр `T=u/v`, затем
вычисляются уравнение и начальные точки. Каждая специализация проверяется:
общая независимость сечений не подменяет проверку конкретного параметра.
Это новые специализации известного семейства, а не построение нового
семейства с общим рангом 32.

`CandidateSampler.cs` перебирает детерминированную псевдослучайную выборку
примитивных пар `|u|≤H`, `1≤v≤H`. Это выборка с возвращением, а не полный
перебор прямоугольника. Число сырых попыток ограничено восьмикратным числом
запрошенных примитивных пар. Очередь сохраняемых параметров ограничена.

Для приоритета используется сумма по простым:

```text
S(B) = Σ log(#E(F_p)/p).
```

Простые 2 и 3 и вырожденные редукции данной модели пропускаются. Этот балл —
эвристика отбора, он не является рангом, нижней или верхней границей ранга.
Локальные подсчёты не вызывают глобальные ранговые процедуры PARI.

По умолчанию:

1. Предвычисляются таблицы редукций семейства по простым до 1021 и обратные
   элементы для ненулевых знаменателей. Во время отбора используются
   обращения к таблицам вместо повторного модульного возведения в степень.
2. Из миллиона примитивных выборок сохраняются 512 параметров.
3. После пересчёта до 4093 остаются 64, после 16381 — 24.
4. Для этих 24 отдельно вычисляется вклад простых от 16381 до 65521.
   Список фиксируется перед этим этапом. Затем баллы используются при выборе
   порядка поиска; это не статистически нетронутая контрольная выборка.
5. Вычисляются 17 общих точек каждого кандидата и их точный сертификат.

Из очереди исключаются повторные `j`-инварианты и `j` известной рекордной
кривой. Это достаточная проверка отличия от неё с точностью до изоморфизма,
но не проверка мировой новизны. Она также консервативно исключает некоторые
неизоморфные над Q квадратичные скручивания с тем же `j`.

Есть второй источник кандидатов: `prepare_grid_candidates.py` читает только
параметры и баллы старого решета. Все 17 начальных точек снова вычисляются
из формул, старые файлы найденных точек не загружаются. Контрольный рекордный
параметр также исключается.

## Распределение поиска точек

`record_hunt.py` чередует три порядка начальной очереди: общий балл,
вклад последних простых и фиксированную случайную перестановку.
Бюджеты задаются накопленным временем на кривую. Например:

| Этап | Число кривых | Накопленное время поиска на кривую |
|---|---:|---:|
| Короткая попытка | 12 | 15 с |
| Продолжение | 4 | 60 с |
| Глубокая попытка | 2 | 240 с |

Кандидаты продвигаются прежде всего по **доказанной нижней границе**, затем
по вкладу последних простых и общему баллу. Очередь содержит также ранее
приостановленные кривые: при одинаковых границах или ошибках они могут
вернуться в работу. Отсутствие прироста не означает малого точного ранга.

Каждая кривая имеет собственный вход, каталог заданий, журнал и состояние.
Продолжение вызывает неизменённый первый алгоритм с `--resume`. Сохраняются
все его точки и уже выполненные попытки. Параллельно по умолчанию работают
две кривые, по четыре процесса поиска точек на каждую.

Мониторинг читает дописываемый журнал stdout. Чтение заменяемого JSON во время
работы исключено: обычный открытый файл в Windows мог мешать атомарной замене
файла состояния. Этот дефект выявлен в первом техническом пробном запуске и
исправлен в версии 2 управляющего кода.

После последнего этапа лучшая кривая проходит полный аудит происхождения
точек и отдельную проверку независимости на Python. Только после этого
появляется `best-verified.json`. Найденная цель завершает следующие этапы;
уже запущенные параллельные попытки текущего этапа заканчивают свои бюджеты.

## Команды

Сборка и новая выборка параметров:

```powershell
dotnet build tools/RankHunt/RankHunt.csproj -c Release --no-restore -p:NuGetAudit=false
dotnet tools/RankHunt/bin/Release/net8.0/RankHunt.dll sample --samples 1000000 --height 1000000 --keep 512 --refine-keep 64 --final-keep 24 --prime-bound 65521 --workers 8 --seed 20260914 --output artifacts/record-hunt/my-candidates
python tools/RankHunt/record_hunt.py --candidates artifacts/record-hunt/my-candidates --output artifacts/record-hunt/my-search --counts 12 4 2 --seconds 15 60 240 --point-workers 4 --parallel-curves 2 --target 32
```

Другой источник кандидатов — сохранённое решето:

```powershell
python tools/RankHunt/prepare_grid_candidates.py --input artifacts/rank-hunt/h10000 --output artifacts/record-hunt/grid-candidates
python tools/RankHunt/record_hunt.py --candidates artifacts/record-hunt/grid-candidates --output artifacts/record-hunt/grid-search --counts 6 2 1 --seconds 20 90 300 --target 32 --previously-studied
```

Выходные каталоги должны быть новыми. Незавершённую кампанию можно продолжить
теми же аргументами с `--resume`; проверяются исходные файлы, код, сборка и
политика. Для другого бюджета или политики нужен отдельный каталог.
Флаг `--previously-studied` записывает контекст опыта в аудит, а не меняет
математическую проверку.

Никаких вызовов `ellrank`, `ellrankinit`, `ell2cover`, `ellanalyticrank` или
`ellgenerators` этот конвейер не выполняет. Высоты известных точек и LLL
служат только поиску; доказательство нижней границы остаётся точным.

## Что ещё предстоит установить

Успешное восстановление 17 → 31 на одной кривой не определяет вероятность
нахождения новой кривой ранга ≥32. Теперь отдельно измеряются качество
отбора параметров, прирост на кривых и стоимость поиска. Для заявления
нового рекорда нужны как минимум 32 независимо проверенные точки;
для заявления новой кривой — дополнительная проверка по опубликованным
каталогам. Отправка результатов в каталоги в этот конвейер не входит.

Первичный каталог и формат математической проверки:
[ICARM](https://elliptic-rank.icarm.cloud/api). Семейство ICARM302 следует
отличать от семейства Элкиса: это различие прямо отмечено в
[статье Элкиса 2026 года](https://arxiv.org/html/2608.25406v1).
