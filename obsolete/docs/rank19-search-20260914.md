# Следующий этап: доказанная нижняя граница 19

14 сентября 2026 года. Построены и проверены 254 специализации семейства ICARM
№302 с **19 независимыми рациональными точками**. Дополнительно получены более
компактные примеры через вспомогательную эллиптическую кривую. Доказана нижняя
граница 19, верхняя граница не вычислялась. Результат не является рекордом;
мировая новизна конкретных примеров не устанавливалась.

Сохранённый компактный пример получается при

\[
T=\frac{22725085445547885594120613332039420088}
{325905743588483439085964217624588672057}.
\]

Уравнение в целочисленной модели семейства и все 19 точек находятся в
`results/rank19-20260914/rank19.json`. Длины коэффициентов a1, a2, a3, a4 равны
83, 164, 245 и 327 десятичным цифрам; a6=0. Это компактный пример относительно
первой партии, но коэффициенты всё ещё велики. Его нижняя граница независимо
проверена C#-библиотекой проекта и ранее аудированным Python-проверяющим кодом.
Сертификат сохранён в `rank19.certificate.json`; BSD и GRH не используются.

## Как получен результат

Из матрицы высот и 17 уже известных сечений построены 318 квадратичных
сечений. Для каждого вычислена факторизация на модели с выделенным квадратом

\[
\lambda^2(x^3+A_2x^2+A_4x+A_6)-(ax-c)^2
=(\lambda^2x-N)(x^2+ux+v).
\]

Все коэффициентные тождества проверены точно. Дискриминант квадратного
множителя записан как `u²−4v=S²H(T)`, где H имеет степень 2. Условие
`U²=H(T)` даёт дополнительную рациональную точку на исходной кривой.

После удаления повторов осталось 126 разных H. Для всех найдены рациональные
параметризации. Из пар следовых векторов с абсолютным скалярным произведением
7 получены 254 рациональные точки пересечения соответствующих сечений. Это
начальные точки на кривых, задаваемых двумя условиями квадрата одновременно.

Подстановка параметризации первой коники превращает второе условие в гладкую
квартику `z²=F(w)`. На ней проведена парабола с касанием порядка 3 в известной
рациональной точке; оставшееся пересечение снова рационально. Полученные
параметры проверены подстановкой, затем к 17 исходным точкам добавлены точки
от обоих квадратичных сечений. Для всех 254 параметров получен точный
сертификат границы 19. Проверялись также остальные 124 коники: в этой партии
третьей дополнительной точки они не дали.

Более компактный пример использует сечения с индексами 283 и 292. Соответствующая
квартика преобразована во вспомогательную эллиптическую кривую. Обратное
преобразование проверено символически и для каждой возвращённой точки. На
вспомогательной кривой независимо доказана нижняя граница **2**: сертификат
учитывает её рациональное 2-кручение. Отчёт PARI `[3,3]` не использован как
независимый сертификат ранга 3.

Таким образом, у вспомогательной кривой бесконечно много рациональных точек.
Два новых сечения вместе со старыми 17 независимы, что подтверждается
специализацией с сертификатом 19. По теореме о специализации это даёт
бесконечно много специализаций с границей 19. База этого семейства —
вспомогательная эллиптическая кривая; параметрами служат её рациональные точки.
Принцип объединения двух квадратичных замен и перехода к такой базе описан
в [разделе 3 статьи Элкиса](https://arxiv.org/html/2608.25406v1).
Здесь он применён к данным семейства №302, опубликованного в
[ICARM](https://elliptic-rank.icarm.cloud/curve/302/commentary-history).

Для некоторых параметров независимость теряется. Например, при `T=2489/7084`
наш набор из 19 точек даёт сертификат только 18. Это не верхняя граница ранга.
Программа всегда проверяет конкретную специализацию.

## Время и ускорение

| Этап | Измеренное время |
|---|---:|
| Построение и проверка 318 квадратичных сечений | 0,476 с |
| Параметризация 126 разных коник | 0,088 с |
| Поиск 254 общих рациональных точек | 0,600 с |
| Шаг по квартикам и получение 254 параметров | 0,067 с |
| Построение точек, точная сертификация и сохранение 254 результатов до оптимизации | 6,248 с |
| Та же сертификация после оптимизации | 4,181 с |

Измерения сделаны на этой машине. Последнее сравнение даёт ускорение примерно
**1,49 раза**. Для всех 254 выходных файлов уравнения, точки и результаты
сертификации до и после оптимизации совпали точно. Сумма замеров оптимизированных
основных этапов — около 5,4 с без запусков Python и сборки .NET. Это время
вычисления подготовленным кодом, а не время разработки.

В `Structured302.cs` рациональная схема Горнера заменена вычислением общих
целочисленных однородных мономов: большие сокращения дробей больше не
повторяются для каждого коэффициента каждого сечения. В `BisectionSearch.cs`
проверка квадрата выполняется для целочисленного однородного H; предварительно
отбрасываются отрицательные значения и невычеты по модулю 64. Последняя
проверка всегда точная. Сокращён также промежуточный вывод в консоль.

В дополнительном поиске на вспомогательной кривой получено 88 разных
параметров: 87 дали границу 19, один — 18. Размеры числителя и знаменателя
лучшего сохранённого параметра не превышают 39 цифр. Наименьший такой размер
в первой партии из 254 параметров был 94 цифры.

## Попытки пройти выше

На сохранённом примере с границей 19 запущен поиск через квартики с высотой
1000000 и 19 опорными точками. Он достиг лимита 30 с, не завершив весь поиск,
и не дал дополнительных точек. Для малой специализации `T=2489/7084` запущен
PARI `ellrank` с известными точками и усилием 2; он также достиг лимита 30 с.
Оба запуска использовали минимальную модель и предел стека 512 МБ.

**Граница 20 пока не доказана.** Эти незавершённые поиски не доказывают
отсутствие дополнительных точек. Ранг 32 и вероятность его достижения в
этой конструкции не установлены. Текущий полезный результат — воспроизводимая
генерация примеров с границей 19 и более быстрый этап их проверки.

## Воспроизведение

Нужны .NET 8, стандартный Python и PARI/GP из
`artifacts/native-validation/gp.exe`. SymPy и компилятор C++ не требуются.
Проверенные коэффициенты и матрица высот сохранены в `tools/RankHunt/Data`.
Основному поиску распакованный архив больше не нужен.

Команды из корня репозитория, PowerShell:

```powershell
dotnet build tools/RankHunt/RankHunt.csproj -c Release -p:RestorePackagesPath=C:\Users\Profit77\.nuget\packages -p:NuGetAudit=false
python tools/RankHunt/bisection_hunt.py construct
python tools/RankHunt/bisection_hunt.py parametrize
python tools/RankHunt/bisection_hunt.py intersections
python tools/RankHunt/bisection_hunt.py advance
dotnet tools/RankHunt/bin/Release/net8.0/RankHunt.dll bisections --input-dir artifacts/bisection-hunt --output artifacts/bisection-hunt/replay --limit 318
python tools/RankHunt/test_hunt.py
dotnet tools/RankHunt/bin/Release/net8.0/RankHunt.dll verify --input results/rank19-20260914/rank19.json
```

Дополнительный ограниченный поиск на вспомогательной кривой:

```powershell
python tools/RankHunt/auxiliary_hunt.py --start 251 --limit 1 --radius 3 --combinations box --max-parameter-digits 100 --effort 2 --timeout 30 --output artifacts/bisection-hunt/aux-replay
dotnet tools/RankHunt/bin/Release/net8.0/RankHunt.dll bisections --input-dir artifacts/bisection-hunt/aux-replay --output artifacts/bisection-hunt/aux-replay/certified
```

В новой версии вспомогательного поиска фиксируется начальное состояние
генератора случайных чисел PARI. Самый компактный пример получен предыдущим
запуском PARI, поэтому состав найденных там генераторов может отличаться.
Его точные координаты, исходная точка квартики и сертификат сохранены;
повторная проверка результата от повторения случайного поиска не зависит.

Сборка завершилась без ошибок и предупреждений; прошли **12 интеграционных
тестов**. Новые проверки включают построение пары коник с нуля из сохранённых
сечений, переход по квартике, точный обратный переход со вспомогательной
кубики, сертификацию 19, специальный параметр с границей 18 и отклонение
испорченной формулы. Ошибки CLI завершаются кодом 1, без ожидания аварийного
обработчика Windows.

В `results/rank19-20260914` сохранены `rank19.json`, `rank19.certificate.json`,
`auxiliary.json`, `auxiliary.certificate.json`, `pair19.json`,
`proof-checks.json`, `search-summary.json` и `further-search.json`.
Исходные журналы и остальные примеры находятся в `artifacts/bisection-hunt`.
